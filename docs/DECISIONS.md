# DECISIONS

Decisions made during planning and building. Newest first. Format: date — decision — why — who.

- 2026-10-24 — Opening balances are the oldest debt and are settled first; they carry an optional month count (`ledger_entries.months_pending`, import column, seed from docs/02 §12). Unpaid months = months × unpaid share, rounded up — docs/06 §6 counts months by unpaid bills, but imported arrears are not bills — M6 build session, to be confirmed.
- 2026-10-24 — Until Q-008 is answered, payments settle a bill as a whole and interest runs only on charges still unpaid (payments count against charges first) — the gentler reading for residents; easy to change in one place — M6 build session.
- 2026-10-24 — Allocations are never deleted: a reversal sets `reversed_at` and re-runs allocation for the flat — docs/05 "never delete financial records" — M6 build session.
- 2026-10-24 — Email provider recommendation: Resend (free tier, simple API) behind the notifier interface; SMS later via an Indian DLT-registered provider such as MSG91 once the business is registered — the Founder asked us to recommend — M6 build session; to be confirmed by the Founder.
- 2026-10-24 — Bill PDFs are rendered when first opened and then stored, not inside the approval transaction (docs/04 §8 and docs/07 M5 put them in it) — a font or renderer failure must never block or roll back money records; the bill's figures are fixed at approval either way — M5 build session, to be confirmed by the Co-founder (Engineering).
- 2026-10-24 — Interest is charged from the later of (due date + grace days) and the previous approved run's bill date, up to the new bill date, on unpaid charges only — docs/06 §5 formula; prevents charging the same days twice; Q-002 still open — M5 build session.
- 2026-10-24 — Complaint photos: JPEG, PNG or WebP checked by content, at most 3 per complaint, stored as `attachments` (owner_type `complaint`); the PWA shrinks photos to 1600 px JPEG before upload — docs/04 §7 "validate uploads by content", slow phone networks — M8 build session.
- 2026-10-24 — Complaint status moves: Open → In progress / Resolved / Closed; In progress → Open / Resolved / Closed; Resolved → In progress / Closed; Closed → In progress (reopen). Reopening clears resolved/closed dates and resident feedback; complaint updates are append-only — docs/02 §8 flow with a way back — M8 build session, to be confirmed.
- 2026-10-24 — Consultants and auditors have no access to complaints (403) — docs/02 §2 lists only admin, treasurer and committee for "Complaints: manage" — M8 build session.
- 2026-10-24 — Complaint hooks and UI (form, status pill, history, photos) live in `packages/shared/src/complaints/` because both apps use them — M8 build session.
- 2026-10-24 — The billing job reads societies through a read-only `scheduler_read` policy enabled by `app.job = 'scheduler'`; all writes still happen per society inside its RLS context — the job must find societies without a user — M5 build session.
- 2026-10-24 — Approval re-computes the charges and refuses (`RUN_STALE`) if anything changed since the draft — what is approved must be exactly what was reviewed — M5 build session.
- 2026-10-24 — Saving a charge head counts as its approval (`approved_by` = the admin, treasurer or consultant who saved it); no separate approval step — docs/02 §5 says heads are "approved by the committee" without a workflow — M4 build session, to be confirmed.
- 2026-10-24 — "Per member" (education fund) counts owners and joint owners active in the period; tenants and delegates are not members — co-operative membership is the owner's — M4 build session, to be confirmed with the consultant.
- 2026-10-24 — A flat missing any input a head needs (carpet area, water taps, construction cost) is left out of the whole run, not just that head; equal splits are shared among the flats billed — docs/06 §2 "flat excluded from the run until fixed", applied to every input — M4 build session.
- 2026-10-24 — Legal percents reach the screens only through the API (`/charges/standard-heads` reads `legal_parameters`); front ends hard-code no legal value — CLAUDE.md §1.2 — M4 build session.
- 2026-10-24 — Excel import keeps warnings importable and errors skipped; confirm re-checks against the database; issues are i18n keys with parameters, never English text from the backend — docs/02 §4 "never import silently" and five UI languages — M3 build session, to be confirmed.
- 2026-10-24 — Tests log in as `app_backend_test`, a role that inherits `app_backend`'s grants, because Postgres roles are server-wide and tests must not change a developer's local password — M3 build session.
- 2026-10-24 — Demo seed layout (flat numbering per wing/floor) is chosen to contain every flat listed in docs/02 §12 and reach the stated flat counts; bill day 1 and due after 15 days are demo values only — docs give counts but not numbering — M3 build session, to be confirmed.
- 2026-10-24 — The migration creates `app_backend` without LOGIN; each environment enables login with its own password outside the migration — no secret ever sits in the repo — M2 build session, to be confirmed by the Co-founder (Engineering).
- 2026-10-24 — Local-only dev sign-in (`POST /api/v1/dev/token`, mounted only when `APP_ENV=local` and a JWT secret is set; front ends show it only with `VITE_DEV_SIGN_IN=true` in dev builds) — lets anyone preview and test the apps without a Supabase project — M2 build session, to be confirmed.
- 2026-10-24 — Until email sending (M9), invite links are shown to the admin once, to copy and share; tokens are random, stored only as SHA-256, single use, scoped to one society, and bound to the invited email when one is given — invites must work before an email provider is chosen — M2 build session, to be confirmed.
- 2026-10-24 — Society routes return 404 (not 403) to people who are not members, so another society's ids are never confirmed; members without the needed role get 403 — docs/07 M2 acceptance — M2 build session.
- 2026-10-24 — Front-end data layer: `@supabase/supabase-js` 2.118 for sign-in, TanStack Query 5 for API calls (hooks in `packages/shared/src/api`), API types generated with `openapi-typescript` 7 from the backend's OpenAPI (`pnpm --filter @societyiq/shared api:generate`) — stack in CLAUDE.md §3 and docs/04 §3 — M2 build session.
- 2026-10-23 — Front-end toolchain pinned for M0: Vite 8, React 18.3, Tailwind 4 (`@tailwindcss/vite`), Vitest 5, ESLint 10 with typescript-eslint; TypeScript held at 5.9 because typescript-eslint does not support TypeScript 7 — React 18 is the decided stack (CLAUDE.md §3); the rest are current releases — M0 build session, to be confirmed by the Co-founder (Engineering).
- 2026-10-23 — `packages/shared` exports TypeScript source (no pre-build step needed by apps); `tsc` still type-checks and builds it — simpler dev loop — M0 build session, to be confirmed.

- 2026-10-23 — Billing follows the statutory apportionment of MCS Rules 106C-12 and 106C-11 (2026), with legal limits stored in a versioned `legal_parameters` table — law requires it; limits change — The Founder (from the Legal & Society Advisor's feedback).
